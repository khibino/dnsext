# clove: KSK のロールオーバーの手順

clove の KSK に関する設計と、KSK のロールオーバーの手順書です。
鍵ファイルについては [ZSK.md](ZSK.md)、署名とシリアルについては [SERIAL.md](SERIAL.md) を参照してください。

## 設計

- 公開する KSK は、`<clove-dir>/<zone>/` にある `.ksk` ファイルのうち、最も新しい 1 本だけです。
- KSK は DNSKEY の RRset だけに署名します。
- 自動のロールオーバーはありません。親の DS を変える必要があるので、運用者がこの手順書に従って行います。
- KSK のファイルが 1 本も無いときは、新しく作ります。
  - それまで鍵を持っていたゾーンなら、警告を出します。
  - 新しい KSK の DS を親に載せるまで、ゾーンは bogus になります。
- 鍵ファイルの `Digest` は、その鍵の DS のダイジェストそのものです。

## 方式

- clove は KSK を 1 本しか公開しません。
- そのため、新旧 2 本の KSK で DNSKEY の RRset に署名する Double-Signature 方式は使えません。
- 親に新旧 2 つの DS を置く、Double-DS 方式（RFC 6781 Sec 4.1.2、Figure 5）で行います。

## 前もって調べておくこと

- `T_dnskey`：ゾーンの DNSKEY の TTL。apex の SOA の TTL です。
- `T_ds`：親の DS の TTL。
- 下流のセカンダリが追いつくまでの時間。clove の下流と、親の下流の両方です。
  - NOTIFY が届けばすぐですが、届かなければ SOA の refresh まで遅れます。

## 手順

### 1. 新しい KSK を作る（まだ使わない）

- 同じゾーンの設定で、`clove-dir` とポートだけを変えた設定ファイルを作ります。
  - `ksk-algo` と `ds-digest` は、本番と同じにします。
  - source はファイルにします。本番のゾーンファイルの写しで構いません。
- その設定で clove を一度起動して、止めます。
  - `<別の clove-dir>/<zone>/` に、新しい `.ksk` ファイルができます。
  - いっしょにできる `.zsk` と `serial` は使いません。
- 本番の `clove-dir` には、まだ置きません。clove は最も新しい KSK を使うので、置いた時点で切り替わってしまいます。

### 2. 新しい KSK の DS を、親に足す

- 新しい `.ksk` ファイルの値から、DS を組み立てます。

```
<Zone> IN DS <KeyTag> <Algorithm> <DigestAlgo> <Digest>
```

- 親に、古い DS と並べて足します。
  - 親も clove でファイルから配っている場合は、親のゾーンファイルに書いて SIGHUP を送ります。中身が変われば、シリアルは自動で上がります。
- `dig DS <zone>` で、親とその下流のすべてから、DS が 2 つ返ることを確かめます。

### 3. 待つ

- `T_ds` に、親の下流が追いつくまでの時間を足しただけ待ちます。
- 古い DS だけの RRset が、キャッシュから消えるのを待つためです。

### 4. KSK を切り替える

- 新しい `.ksk` ファイルを、本番の `<clove-dir>/<zone>/` に置き、clove を再起動します。
  - SIGHUP では切り替わりません。ソースが変わらない限り、署名し直さないためです。
  - 起動したときは、必ず署名し直し、シリアルを上げます。
  - 古い `.ksk` ファイルは、残しておいても使われません。
- `dig DNSKEY <zone> +dnssec` で、次のことを確かめます。
  - KSK（flags 257）が、新しい鍵タグになっている。
  - DNSKEY の RRSIG が、その鍵タグで作られている。
  - clove の下流も、同じになっている。

### 5. 待つ

- `T_dnskey` に、clove の下流が追いつくまでの時間を足しただけ待ちます。
- 古い KSK を含む DNSKEY の RRset が、キャッシュから消えるのを待つためです。

### 6. 古い DS を、親から外す

- 外したら、古い `.ksk` ファイルを、ゾーンのディレクトリの外へ移します。

## 注意

- 4 を 3 より前にしないでください。古い DS しかキャッシュに無いリゾルバから見て、ゾーンが bogus になります。
- 6 を 5 より前にしないでください。古い DNSKEY をキャッシュに持つリゾルバから見て、ゾーンが bogus になります。
- KSK のファイルを失ったときは、clove が新しい KSK を作り、警告を出します。
  - 新しい DS を親に載せるまで、ゾーンは bogus です。
  - 2 から 6 を、待ち時間を待たずにすぐに行うしかありません。
