# clove: ゾーンの読み込みと更新の設計

clove がゾーンをいつ読み込み、どう更新するかに関する設計書です。
シリアルと署名については [SERIAL.md](SERIAL.md)、ZSK のロールオーバーについては [ZSK.md](ZSK.md) を参照してください。

## ゾーンごとのスレッド

- ゾーンごとに 1 本のスレッド（`syncZone`）が、読み込みと更新を受け持ちます。
- 起動時には、ゾーンを読み込まずに、すぐに問い合わせを受け付け始めます。
  - 上流に届かないゾーンが、ほかのゾーンの起動を待たせないためです。
  - 読み込みは、各ゾーンのスレッドが、待つ前に一度行います。
- スレッドは、「待つ」と「読み込む」を繰り返します。
  - 待つのは、時間切れになるか、起こされるまでです。
  - 起きたら、署名するゾーンではまず ZSK のロールオーバーの時期かを確かめ、それから読み込みます。

## ゾーンの状態

ゾーンは、次の 2 つの旗で状態を表します。

- `zoneReady`：答えられるデータを持っているか。
- `zoneFailing`：直前の読み込みが失敗したか。

| `zoneReady` | 問い合わせへの答え | AXFR の求め | NOTIFY を送るか |
|---|---|---|---|
| True | データから答える | 許された相手には渡す | 返すシリアルが変わったときに送る |
| False | SERVFAIL（AA なし） | 拒否する | 送らない |

- 作ったばかりのゾーンは、`zoneReady` が False です。
- 読み込みに成功すると、True になります。
- 読み込みに失敗しても、それまでのデータを持っていれば、True のままです。ただし、上流から受け取るゾーンは、expire を過ぎると False になります（後述）。

## 待つ長さ

起きるのは、次の時間切れのうち早い方です。署名しないゾーンには、ロールオーバーの時間切れはありません。

| ゾーン | 状態 | 読み込みの時間切れ |
|---|---|---|
| ファイルから | 読み込めていて、直前に失敗した | SOA の retry |
| ファイルから | それ以外 | なし |
| 上流から | 読み込めていない | 10 秒 |
| 上流から | 直前に失敗した | SOA の retry |
| 上流から | それ以外 | SOA の refresh |

- 署名するゾーンは、これに加えて `zsk-rollover-duration` でも起きます。
- 時間切れの長さは、待ち始めるときの SOA から取ります。
- ファイルから読み込めていないゾーンは、空の DB の SOA に頼れないので、時間切れを持ちません。
  - SIGHUP か NOTIFY を待ちます。署名するゾーンなら、ロールオーバーの時間切れでも起きます。

## 起こされる契機

- **SIGHUP**：すべてのゾーンを起こします。ログのファイルも開き直します。
- **NOTIFY**：そのゾーンを起こします（RFC 1996 Sec 4.7）。
  - どの NOTIFY を受け付けるかは、[ACCESS.md](ACCESS.md) を参照してください。
  - 受け付けない NOTIFY には REFUSED を返します。
- 起こす合図は 1 つの旗なので、何度起こしても 1 回分にまとまります。
  - 読み込んでいる最中に起こされたときは、次に待つときにすぐ起き、もう一度読み込みます。

## 読み込み

- ファイルから：
  - 毎回ゾーンファイルを読みます。
  - 前回取り込んだレコードと同じなら、新しい版とはみなしません（署名するゾーンのみ。[SERIAL.md](SERIAL.md)）。
- 上流から：
  - 前回のシリアルがあれば、まず SOA を問い合わせます。
    - 上流のシリアルの方が大きければ、AXFR でゾーン全体を受け取ります。
    - そうでなければ、新しい版は無い（`Unchanged`）とします。
  - 前回取り込んだレコードが無ければ、シリアルを比べずに AXFR します。
  - SOA の問い合わせに答えが無い、または答えを信用できない（TSIG が合わない、など）ときは、`Unreachable` とします。
  - AXFR が途中で失敗したときは、例外として扱います。
- 新しい版があれば、DB を作り直します。署名するゾーンは、署名し直してから作り直します。
- 新しい版が無ければ、いまの DB をそのまま使います。ただし、署名するゾーンでロールオーバーの時期なら、署名し直します。
- 読み込みの結果、返すシリアルが変わったときだけ、`notify-addrs` に NOTIFY を送ります。

## 失敗

- 読み込みが例外で失敗したとき（ゾーンファイルが読めない、AXFR が途中で失敗した、署名に失敗した、など）：
  - いまの DB をそのまま使います。
  - `zoneFailing` を True にして、次は SOA の retry で起きます（#310）。
- 上流が `Unreachable` のとき：
  - これも失敗として扱い、`zoneFailing` を True にします。
- 次に成功すれば、`zoneFailing` は False に戻ります。

## expire（上流から受け取るゾーンのみ）

- 上流が最後に答えた時刻から、SOA の expire を過ぎると、ゾーンを `zoneReady` False にします（RFC 1035 Sec 3.3.13）。
  - そのゾーンについて、もう権威を持って答えられないからです。
  - 以後は、読み込めていないゾーンと同じく SERVFAIL で答え、10 秒ごとに読み込みを試みます。
- 最後に答えた時刻の初期値は、ゾーンを作った時刻です。
- expire かどうかは、読み込みに失敗したときに確かめます。
- ファイルから読むゾーンは、expire しません。
